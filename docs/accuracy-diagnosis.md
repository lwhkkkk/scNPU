# 全量 PCA 分数绝对误差门限诊断

2026-11-04 对比旧流程 `artifacts/legacy-baseline-20261104T105820Z` 与新流程 `artifacts/new-build`。复现脚本为 `benchmarks/diagnose_scores.py`；原始证据在 `artifacts/score-diagnosis.json`。

**旧 SVD 一致性比较未通过；新实现对完整 CPU FP64 参考全部通过。两条记录同时保留，未修改门限。** 原门限为正交 Procrustes 对齐后的 score 最大绝对差 ≤0.002，旧/新比较实测 0.0038687997。表达矩阵一致、子空间接近和采样邻居相同，都不能替代这项门限。

## 定位结果

全量扫描 1,306,127 行分数，最大差出现在零基行号 **902012、PC50**，barcode `GATCTAGAGAAGAAGC-93`：

| 指标 | 数值 |
|---|---:|
| 旧流程分数 | 281.833251953125 |
| 新流程正交对齐后分数 | 281.8371207528295 |
| 绝对差 | 0.00386879970449 |
| 相对该元素差 | 1.37273e-5 |
| 此细胞最大的绝对 PC 分数 | 564.8056640625 |

使用完整精度 CSV loadings 重新计算 Procrustes，**全量**最大差为 0.0038698978；使用最小二乘线性映射替代正交映射作诊断，最大差为 0.0039588771。两者均未消除差异；这些诊断映射没有替换既定验收指标。

## 误差分解

取 20 个块内最差细胞，对同一保存的 FP32 表达矩阵使用 CPU FP64，按**各流程自己的 CSV loadings、均值、标准差**重新投影。CSV 保留原始求解器输出精度；旧 SVD 输出本就是 FP32，后续存成 FP64 CSV 不会增加有效精度。

最大差位置可以分解为：

| 来源 | 对该元素差值的有符号贡献 |
|---|---:|
| 基底在另一 top-50 子空间之外的方向残差 | +0.00396017817492 |
| 正交对齐无法吸收的基底非正交/尺度分量 | −0.00009007744128 |
| 两侧实际投影相对各自 FP64 投影的合并误差 | −0.00000130102913 |
| 均值/标准差差异 | 约 1.14e-13 |
| 上述分解的数值残差 | 约 −1.23e-13 |

旧/新均值和标准差均完全一致。旧 loadings 的 `max(abs(V.T@V-I))` 为 1.73e-6，新 loadings 为 1.54e-15；非正交性确实存在，但在最大差位置并非主要贡献。

该位置的旧、新原始投影相对各自 FP64 重算分别为 −2.43e-5、−2.56e-5；它们大体抵消。使用 H5AD FP32 loadings 而非 CSV loadings 引入的对齐差仅约 −1.10e-6。**因此不能把本次失败主要归因为投影舍入或导出 loadings 的 FP32 压缩。**

20 个选定细胞中，两侧单独投影的最大绝对误差分别为 2.15e-4、2.44e-4；合并后的最大误差为 1.92e-4。这也表明旧流程仅验证首块投影误差的做法不能代表全量最坏值。这里的 FP64 重投影仅覆盖选定细胞，不声称是完整全量投影精度审计。

## 判断与后续

直接证据指向：旧 FP32 SVD 与新 FP64 `eigh` 返回的 top-50 基底存在很小的**子空间方向差异**，在部分高幅度细胞、尤其末端 PC 上被放大；“最小主角余弦极接近 1”不保证逐元素绝对误差小于 0.002。这说明失败的数值来源，并不单凭该比较判断哪个结果更准确。

下一步应使用独立 CPU FP64 完整参考流程，分别评价新流程与旧流程：特征值、特征残差、子空间、分数以及邻居稳定性。保持现有门限并保留此次失败记录；若新流程对可信 FP64 参考通过而对旧 SVD 参考未通过，应明确写出两种比较各自的结果，不能将旧门限标记为通过。

## 补充：完整 CPU FP64 参考验证

随后已完成 `artifacts/new-cpu` 的全量 CPU 参考计算，并以**原先声明的同一组门限**比较 `artifacts/new-build`。结果全部通过；证据为 `benchmarks/evidence/cpu-vs-new-build.json`（远程原始文件：`artifacts/cpu-vs-new-build.json`）。

| 指标 | 新 NPU 流程对 CPU FP64 参考 | 原门限 |
|---|---:|---:|
| 表达矩阵最大绝对差 | 0 | ≤2e-4 |
| 特征值最大相对差 | 1.10384e-7 | ≤2e-4 |
| loading 子空间最小余弦 | 0.999999999999013 | ≥0.9999 |
| 对齐分数相对 Frobenius 差 | 2.54946e-7 | ≤2e-4 |
| 对齐分数最大绝对差 | 0.000513800897 | ≤0.002 |
| 采样邻居重合率 | 1.0 | ≥0.99 |

参考流程与新流程共享前处理实现和同样的 FP32 表达数据；**dense Gram、特征分解、投影分别在 CPU FP64 重新计算**，没有复用 NPU Gram 或 NPU scores。它为 PCA 数值路径提供独立高精度计算参考，但不能单独排除共享前处理逻辑错误；前处理另外由 Scanpy 对照测试覆盖，PCA API 另有 sklearn 对照测试。

邻居验证范围仍然是固定种子的 2048 个细胞、样本内部 `k=15`，不代表完整百万细胞邻居图验证。新 NPU 流程对该 CPU 参考通过，与其对旧 FP32 SVD 基线的绝对误差门限失败**同时成立**；旧比较失败记录完整保留。

随后直接比较 CPU FP64 参考与旧 SVD，旧流程的最大对齐分数差为 **0.004051529**，同一 0.002 门限失败（其余五项通过）。融合版对 CPU 参考最大差为 **0.000475635**，全部六项通过。证据分别为 `benchmarks/evidence/cpu-vs-legacy.json` 和 `cpu-vs-new-fused.json`。这支持以完整 CPU FP64 计算作为数值参考、保留新 CPU eigh 方案；不通过放宽门限或复现旧求解器误差来获得表面一致。
